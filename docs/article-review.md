# 記事の内容確認（人間がやる）

記事は Claude が書き、**公開（main へのマージ）の前に人間が内容を確認**します（WEBAPP_BASELINE.md §10-7）。
PR を出すと Cloudflare のプレビュー URL ができるので、そこで実際のページを見て確認します。直したい点は PR のコメントか Claude への指示で伝えてください。

## 毎回見ること

| # | 観点 | 見るところ |
|---|---|---|
| 1 | 事実の正しさ | 分野の説明に間違いや言い過ぎがないか |
| 2 | アプリとの一致 | 記事の説明（ボタン名・手順・条件）がいまのアプリの動きと合っているか。画面写真が古くないか |
| 3 | 表の内容 | 表は計算で作っているので書き間違いはないが、選んだ例や結果が実際に自然か |
| 4 | 日本語・英語の自然さ | 直訳っぽい言い回し、用語の不統一 |
| 5 | 検索用の文言 | 各記事の `title` と `description`（`scripts/pages/<slug>.mjs` の先頭）が、狙う検索語を含み、内容と合っているか |
| 6 | 権利 | 著作権のある歌詞・曲・画像を使っていないか |
| 7 | スマホ | 390px 前後の幅で読みやすいか（表は横スクロール） |

### Claude による校閲で直したこと（WEBAPP_BASELINE.md §10-9）

| 記事 | 直したこと | 根拠（資料） |
|---|---|---|
| ガイド | 「C4 が真ん中のド」：MIDI 60 = C4 の表記（国際式）で書き、アプリの鍵盤の表示と合わせた（ヤマハ式では C3 と呼ぶ場合があるため、アプリの表示に合わせることを優先） | アプリの `noteName()`（MIDI 60 → C4） |
| ガイド・FAQ | 「100 セント＝半音」と、判定の幅（緑・黄）をアプリの `STRICT` から読んで書くようにした（書き写さない） | `scripts/pages/app.mjs` |
| ガイド・FAQ | おすすめキーの説明を、実装どおり「一番低い 5% と一番高い 5% の時間を除く」「−6〜+6 半音と、1 オクターブ下・上」にした | `index.html` の `suggestKey()`・`lineRange()` |
| 運営者情報 | Spleeter の著作権表記を LICENSE ファイルの文言（Copyright (c) 2019-present, Deezer SA.）に合わせた | PyPI の spleeter 2.4.2 の LICENSE |
